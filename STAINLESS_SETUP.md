# Stainless integration

Architecture A: this monorepo orchestrates; each SDK is its own git repo (currently `stainless-sdks/slng-typescript` and `stainless-sdks/slng-python`, eventually `slng-ai/slng-node` and `slng-ai/slng-python`).

## Repo layout (after `stl init`)

```
hong-kong-v1/
├── .stainless/                     # Stainless workspace + config (committed)
│   ├── workspace.json
│   ├── stainless.yml               # API resources, environments, auth
│   └── openapi.json
├── specs/bridges-unmute/           # vendored from gateway-specs (source of truth)
├── streaming/                      # hand-written WebSocket source of truth
│   ├── ts/{client,messages,index}.ts
│   └── python/{client,messages,__init__}.py
├── scripts/
│   ├── sync-specs.sh
│   ├── gen-ws-types.{ts,sh}
│   └── push-streaming.sh           # streaming/* -> sdks/slng-{ts,py}/src/streaming/
├── cli/                            # Bun CLI (not yet implemented)
└── sdks/                           # Stainless's working copies (gitignored)
    ├── slng-typescript/            # own git repo, own remote
    ├── slng-python/                # own git repo, own remote
    └── slng-openapi/               # bundled spec
```

## Day-to-day flow

```bash
bun run sync-specs              # vendor latest from gateway-specs
bun run gen-ws-types            # AsyncAPI -> streaming/ts,python/messages.*
stl preview                     # Stainless rebuilds sdks/slng-*
bash scripts/push-streaming.sh  # copy streaming/* into each SDK's src/streaming/
# inside each SDK, commit + push so Stainless's next regen merges your edits:
(cd sdks/slng-typescript && git add src/streaming src/index.ts package.json && git commit -m "feat(streaming): add WebSocket client")
(cd sdks/slng-python     && git add src/slng/streaming pyproject.toml      && git commit -m "feat(streaming): add WebSocket client")
```

## Why streaming is hand-written

OpenAPI doesn't describe WebSocket protocols. Stainless reads only OpenAPI. So:

- HTTP client → generated by Stainless from `bridges-unmute.oas.yaml`.
- WebSocket client → hand-written ~150 LOC in `streaming/{ts,python}/`.
- WebSocket message types → generated from `bridges-unmute.asyncapi.yaml` via quicktype, in `streaming/{ts,python}/messages.*`.

Stainless preserves the streaming files via 3-way git merges on the SDK's integrated branch. There is **no `patches:` config field** — committing the files inside each SDK repo is the mechanism.

## When you're ready for production

In `.stainless/stainless.yml`:

```yaml
targets:
  typescript:
    production_repo: slng-ai/slng-node    # currently null
    publish:
      npm: true                            # currently false
  python:
    production_repo: slng-ai/slng-python   # currently null
    publish:
      pypi: true                           # currently false
```

Then `stl preview` pushes to the production repos and a tagged release publishes to npm/PyPI.

## On committing the SDK working copies into THIS repo

`sdks/slng-*/` are gitignored by default because each holds its own `.git/` (separate remote, independent history). If you want them tracked here too:

```bash
rm -rf sdks/slng-typescript/.git sdks/slng-python/.git sdks/slng-openapi/.git
# remove the matching lines from .gitignore
git add sdks/
```

Caveat: `stl preview` recreates the inner `.git` on every run, so you'd repeat the `rm -rf` each time. Recommend leaving them gitignored and treating them as build outputs.
